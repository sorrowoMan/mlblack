# 统计建模论文主线建议：从现象分解到白盒风险边界

## 核心判断

这个项目不应该写成“我写了哪些代码、用了哪些模型”。它更像一条完整的统计建模路线：

1. 先定义和构造拥堵指数；
2. 再用时间序列分解判断拥堵变化的主导结构；
3. 用 ARIMAX 做外部因素归因，建立传统统计基线；
4. 用 Nowcasting 白盒方程发现重构交通流瞬时机理；
5. 再切换到严格 Forecasting，删除同日同步变量；
6. 最后用区间预测和 CQR 给出风险边界。

论文应该强调“建模思想递进”，而不是“代码模块堆叠”。

## 推荐论文叙事

### 第一层：现象定义

先说明为什么需要拥堵指数 \(CI\)，以及它如何综合速度、占有率等交通状态信息。STL 结果显示趋势强度高（例如 `trend_strength ≈ 0.877`），季节项弱，说明拥堵指数不是简单周期波动，而是受趋势、事件和状态惯性共同驱动。

这一层的作用是回答：

> 我们研究的对象是什么？它是否值得建模？

### 第二层：传统统计归因

ARIMAX 用于建立可解释统计基线。它把拥堵指数分解为自回归结构和外部协变量影响。结果中 AR/MA 项显著，而许多外部变量的显著性较弱，说明拥堵序列具有强状态记忆，单纯外部因素难以解释全部变化。

这一层的作用是回答：

> 传统统计模型能解释什么，不能解释什么？

它不是最终模型，而是为后续白盒函数搜索提供问题动机。

### 第三层：Nowcasting 机理重构

Nowcasting 模块不是前瞻预测，而是同日状态估计和方程发现。它允许使用 `total_flow`、`avg_speed`、`avg_occ` 等同步变量，目标是从数据中重构交通流瞬时物理关系。

这里的核心贡献不是 RMSE 多低，而是模型能自动发现连续、可解释的方程结构。例如速度约 95km/h 附近的折点、占有率约 20% 附近的 hinge 结构，均可解释为自由流与拥堵流之间的相变边界。

这一层的作用是回答：

> 数据中是否存在可解释的交通物理结构？

### 第四层：严格 Forecasting

Forecasting 阶段必须删除同日 `flow/speed/occ`，只能使用 lag、日历、天气等事前变量。它不能直接复用 Nowcasting 公式，也不能简单把同日变量替换成滞后变量。

正确逻辑是：

> Nowcasting 发现机理结构，Forecasting 在事前变量集合上重新训练，并把已验证的函数族作为候选结构和解释参照。

这一层的作用是回答：

> 在不泄漏未来信息的条件下，模型还能否形成有效预测？

### 第五层：风险边界而非单点预测

最终任务不应只追求点预测 RMSE，而应强调区间预测和风险预警。CQR 的意义在于不强行假设残差分布，而是用校准集给出分布无关的覆盖修正。

因此评价重点应包括：

- RMSE：中心预测误差；
- PICP：真实值落入区间比例；
- PINAW / mean width：区间宽度；
- interval score：覆盖不足与区间宽度的综合惩罚。

这一层的作用是回答：

> 模型能否给调度者一个可靠的风险边界？

## 论文贡献可以这样写

本文的贡献不是简单提出一个新算法，而是提出一条面向交通拥堵风险预警的白盒统计建模路径：

1. 用 STL 和 ARIMAX 建立传统统计解释基线；
2. 用梯度引导的符号函数空间搜索进行 Nowcasting 机理重构；
3. 将同日方程发现与严格前瞻预测明确分离，避免前瞻偏差；
4. 在 Forecasting 阶段结合 native interval head 和 CQR，构造分布无关风险边界；
5. 在预测性能之外保留方程结构、阈值解释和机制审计能力。

## 需要避免的写法

不要把论文写成：

- “本文使用了某某脚本”；
- “本文调用了某某模型”；
- “符号回归比 XGBoost 更强”；
- “Nowcasting 的低 RMSE 证明预测能力强”；
- “同日变量公式可以直接转为前瞻公式”。

更稳妥的写法是：

- “STL 显示拥堵指数以趋势和状态变化为主”；
- “ARIMAX 说明自回归记忆显著，外部变量解释有限”；
- “Nowcasting 用同步变量重构瞬时交通流方程”；
- “Forecasting 删除同步变量，在事前信息约束下重新建模”；
- “CQR 将预测结果转化为可校准的风险边界”。

## 一句话主线

本文不是把一个黑盒模型用于拥堵预测，而是构建了一条从统计分解、因素归因、白盒方程发现到严格区间预测的完整建模链条，使交通拥堵风险预警同时具备预测能力、物理解释和不确定性边界。
